# LongBench v2 基线实验与数据集分析报告

## 1. 基本信息

- **数据集**：LongBench v2（THUDM），共 **503** 条英文四选一选择题，用于评测长上下文理解与推理能力。
- **字段**：`_id`、`domain`（大类）、`sub_domain`（子任务）、`difficulty`（easy/hard）、`length`（short/medium/long）、`question`、`choice_A~D`、`answer`、`context`。
- **评测方式**：0-shot，模板要求模型输出 `The correct answer is (X)`；正则抽取 A/B/C/D，与标准答案比对，抽不到记 0。
- **答案分布**：A=96、B=127、C=148、D=132，无明显单一选项偏向，随机蒙题基线为 25%。
- **数据来源**：HuggingFace `THUDM/LongBench-v2`；论文 arXiv:2412.15204。

## 5. 基线实验设置与结果

### 5.1 实验设置

- **模型**：gpt-5.6-sol、gpt-6-sol（均经 Thingo OpenAI 兼容网关调用，同系列两代对比）。
- **参数**：temperature 0.1，0-shot，max_tokens 1024。
- **评测口径**：1.成功口径：ACC = 答对条数 / 成功评测条数；失败样本不计入分母。2.全量口径：ACC = 答对条数 / 全部评测条数；失败样本也计入分母。

### 5.3 口径说明

- gpt-5.6-sol：成功 460 条、失败 43 条，覆盖率 91.5%；gpt-6-sol：成功 457 条、失败 46 条，覆盖率 90.9%。
- **成功口径**：ACC 分母为成功样本；**全量口径**：分母为全量 503 条，失败与 Invalid 记 0。5.6 正确 278 条（全量 55.3%），gpt-6 正确 300 条（全量 59.6%）。
- 两种口径差异主要来自超窗样本：两模型 Long 档全量口径分别降至 42.6%、40.7%，Code 大类均降至 44.0%。
- Invalid：5.6 为 3 条、gpt-6 为 13 条，均为模型未输出选项字母（多为 `none of the above`），按官方口径记 0。
- **对比口径注意**：两批跑批使用的本地预判阈值（max_context_words）不一致，部分超长题被本地阈值拦下、未实际发送请求；表中超窗数含本地预判拦截，跨模型长上下文对比需结合覆盖率谨慎解读（见问题 5）。

## 6. 模型能力分析

> 以下结论基于各模型成功样本（gpt-5.6 460 条、gpt-6 457 条）；受超窗幸存者偏差影响，long 档与 Code 档分数需谨慎解读（见问题 5）。

### 6.1 整体水平

- gpt-5.6-sol 整体 ACC 60.4%（全量口径 55.3%）；gpt-6-sol 65.6%（全量口径 59.6%），两代均显著高于四选一随机基线 25%，具备基本的长上下文理解与选择能力。
- **代际对比**：gpt-6-sol 全量口径 Overall 提升 4.3 个百分点（55.3% → 59.6%），成功口径提升 5.2 个百分点；易/中长文本与对话历史类任务提升明显，超长上下文与代码库两类短板未改善（见 6.3、6.4）。
- 预测分布：5.6（A=94、B=122、C=122、D=119）、gpt-6（A=91、B=115、C=120、D=118），与标准答案分布（A=86、B=116、C=137、D=121）基本吻合，没有明显偏向某一选项，未出现靠固定猜某个字母蒙分的现象。
- 与官方报告中强模型水平（GPT-4o 50.1%、o1-preview 57.7%、人类 53.7%）的对比需在同口径、同覆盖率下进行，本结果仅作基线参考。

### 6.2 分能力维度解读

| 能力维度 | 对应任务 | gpt-5.6-sol 表现 | gpt-6-sol 表现 | 分析 |
|---|---|---|---|---|
| 结构化数据理解 | Table QA、Knowledge graph reasoning、Structured Data 大类 | Table QA 66.7%、KG reasoning 85.7%、Structured 75.9% | Table QA 53.3%、KG reasoning 100.0%、Structured 75.9% | 知识图谱推理两代都强；表格题 gpt-6 样本更少（15 条），波动较大；Structured 大类两代持平 |
| 长上下文学习（In-context Learning） | Many-shot learning、LIL 大类 | Many-shot 71.4%、LIL 62.9% | Many-shot 95.2%、LIL 75.4% | 两代对比中 gpt-6 在规律归纳与少样本迁移上提升明显 |
| 代码库理解 | Code repo QA | 成功口径 71.0%（31/50），全量 44.0% | 成功口径 71.0%（22/31），全量 44.0% | 两代可评测样本持平，全量口径均受超窗拖累至 44.0%；代码类 token 密度高，未随代际改善 |
| 事件时序推理 | Event ordering | 85.0% | 100.0%（20/20） | 长文本事件先后顺序梳理能力强，gpt-6 满分 |
| 单文档/多文档阅读理解 | Academic、Legal、Literary、Financial、Multi-news、Detective 等 | 多在 56%～62% 区间 | 多在 59%～66% 区间（Multi-news 47.8% 偏低） | 常规长文档问答 gpt-6 整体小幅提升；跨文档整合仍未见明显优势 |
| 长对话历史理解 | Dialogue history QA、Agent history QA | Dialogue 42.1%、Agent history 60.0% | Dialogue 63.2%、Agent history 85.0% | 两代对比中提升最大的维度之一，gpt-6 对多轮对话早期信息的定位与回溯明显改善 |
| 政务/政策类文本理解 | Governmental | 37.5%（easy 77.8% / hard 25.8%） | 35.9%（14/39） | 两代均为最低子任务，难题下的政策文本辨析能力薄弱，代际未改善 |

### 6.3 难度与长度上的表现

- **难度**：两代均为 Easy 高于 Hard（5.6：65.7%/57.1%；gpt-6：74.4%/60.1%），符合预期；难题上模型更容易被干扰信息带偏。gpt-6 在 Easy 上提升 8.7 个百分点，Hard 提升 3.0 个百分点，易题改善更明显。
- **长度（需结合偏差解读）**：成功口径 5.6 为 Short 61.7%、Medium 57.1%、Long 67.6%；gpt-6 为 Short 65.0%、Medium 65.3%、Long 68.8%。全量口径下两代 Long 分别为 42.6%、40.7%，均明显回落——long 档被超窗筛掉一批最长样本，留存样本存在幸存者偏差，成功口径的 Long 偏高不能说明"越长越强"。Medium 档 gpt-6 提升 8.2 个百分点（成功口径），是长度维度上改善最明显的一档。
- **难度×长度交叉（成功口径）**：5.6 的 hard-medium 52.8% 为最低桶；gpt-6 各桶为 easy-short 71.2%、easy-medium 71.3%、easy-long 90.0%、hard-short 62.0%、hard-medium 61.1%、hard-long 50.0%。两代 hard-long 均为难题长文，gpt-6 反而降至 50.0%，说明超长难题仍是 gpt-6 的薄弱区；难度仍是比长度更强的影响因素。

### 6.4 薄弱环节小结

1. **超长上下文承载**：两代分别有 39、42 条超窗未评测，模型在百万词级场景下受窗口硬限制，不具备直接处理能力；gpt-6 全量口径 Long 40.7%，未改善。
2. **代码库理解受窗口拖累**：Code 大类两代全量口径均为 44.0%，可评测样本持平但超窗淘汰了最长的代码题。
3. **高难度政策/政务文本**：Governmental 两代分别为 37.5%、35.9%，均为最低子任务，复杂政策表述下的辨析能力薄弱，代际未改善。
4. **格式遵循（Invalid）**：5.6 有 3 条、gpt-6 有 13 条输出 `none of the above` 未给选项字母；gpt-6 在不确定时更倾向放弃选项，指令遵循反而松动更多。
5. **长对话历史回溯已改善**：Dialogue history QA 由 42.1% 升至 63.2%、Agent history QA 由 60.0% 升至 85.0%，是 gpt-6 提升最明显的能力维度。

## 7. 已发现的问题

### 问题 1：超长上下文超出模型窗口（5.6 39 条 / gpt-6 42 条）

- **现象**：5.6 有 39 条、gpt-6 有 42 条因上下文过长未评测；词数范围 17.1 万～138.1 万，绝大多数集中在 long 档。
- **分布**：Code repo QA、New language translation 占比最高，其余散落在 Academic、Table QA、Financial、User guide QA、Legal、Governmental、Knowledge graph reasoning、Literary。
- **成因**：模型单次上下文存在硬上限；代码、数字、专名的 token 密度高于普通英文，同样词数占用更多 token；百万词级题目超出任何单窗口模型的直接处理范围；
- **口径提示**：本表超窗数含脚本本地预判拦截（词数超过 max_context_words 阈值即不发送），不全是服务端返回的窗口 400；两批跑批阈值不一致，gpt-5.6阈值为200000，gpt-6阈值提高为350000，然而跑gpt-5.6时前一百多条未手动设置阈值，因此超窗条数少于gpt-6可能存在操作误差，不代表gpt-6窗口变小。跨模型超窗数量对比需谨慎。
- **影响**：long 档、Code 档被超窗筛掉一批最难/最长样本，剩余样本的准确率存在幸存者偏差。
- **后续方向**：统一两模型阈值并重跑临界题；更换更大上下文窗口的模型；分段检索（RAG）后再送入模型；分块摘要或递归压缩。

### 问题 2：平台敏感词审核拦截（5.6 3 条 / gpt-6 4 条）

- **现象**：5.6 有 3 条、gpt-6 有 4 条返回 `500 sensitive_words_detected`；5.6 全部属于 New language translation，gpt-6 为 New language translation 3 条、Legal 1 条；词数 9.6 万～26.3 万。经对比溯源，两个模型对应New language translation报错样本相同，而gpt-6多出的Leagl样本因为词数超200000，被gpt-5.6手动阈值拦下，未进行评测。
- **成因**：平行语料含政务表述，被网关关键词审核命中；审核发生在模型推理之前。
- **性质**：属于外部平台限制，非模型能力问题；本地修改 prompt 措辞无法绕过，同一内容重试仍被拦截，且会产生输入计费。
- **后续方向**：更换审核策略不同的渠道重试；通过检索只送相关片段；联系平台管理员确认是否误判并评估放行。

### 问题 3：内容政策拦截（1 条）

- **现象**：gpt-5.6报错样本中1 条 Financial 题目返回 `400 Request blocked by content policy`，输入 171,530 token；题目涉及加密货币（cryptocurrency）现金流，来源为矿企 SEC 10-K 年报，经对比溯源发现该题被gpt-6放行，成功返回并答题正确。
- **成因**：话题级内容政策拦截，与上下文长度无关；报错注明 "Normal input charge applied"，被拦仍计输入费用。
- **性质**：平台政策限制，本地无法解除；与敏感词关键词过滤属于不同层级的审核。
- **后续方向**：换渠道重试确认是否复现；如仍被拦，归入政策拦截未评测，不计入准确率。

### 问题 4：模型拒答/未按格式输出（5.6 3 条 / gpt-6 13 条 Invalid）

- **现象**：成功写入结果但抽不到 A/B/C/D，`pred=None`；模型回复为 `none of the above` / `none of the listed choices`。gpt-6 此类样本明显多于 5.6（13 vs 3）。
- **成因**：LongBench v2 四个选项中仅有一个正确答案，不存在"以上都不是"选项；模型判断四个选项均不匹配，未按要求输出选项字母。gpt-6 在把握不足时更倾向以"都不对"作答，而非在选项中选择。
- **口径处理**：按官方规则，抽不到 `The correct answer is (X)` 记 0，计入错误；这些属于格式/解析失效，与明确选错字母的样本应区分记录，但不人为猜测其意图选项。
- **后续方向**：在 prompt 中强化"必须从 A/B/C/D 中选择"的约束；统计 Invalid 在各子任务的分布，定位模型犹豫的题型。

### 问题 5：幸存者偏差导致分桶结果不可直接横向比较

- **现象**：失败样本高度集中于 long 档和少数 medium；Code Repository Understanding 原始 50 条，5.6 成功 31 条、gpt-6 成功 31 条（均约 19 条超窗），Long 档原始 108 条两模型均只评测到约 60 余条。
- **成因**：超窗淘汰的是最长、最难的一批样本，留存样本被筛选过一轮；各分桶的样本基数和难度结构不一致。
- **影响**：表中 Long 档成功口径偏高、Code 档 71.0% 偏高，不能直接解读为"模型越长文/代码越强"；小样本分桶（Code 31 条、Structured 29 条）方差更大。
- **处理建议**：报告分桶准确率时同时标注各桶成功样本数；跨桶比较需结合覆盖率与样本构成谨慎解读；跨模型对比应在统一阈值、统一覆盖率口径下进行。

### 问题 6：数据集本身的结构特点

- **任务类型**：全部为四选一选择题，评分可靠（ACC），避免了生成式任务的主观评分；但也限制了对自由生成能力的评测。
- **选择题存在随机蒙对空间**：四选一随机基线为 25%，模型在不确定时仍有 1/4 概率蒙对；单题准确率无法区分"真正理解"与"侥幸猜中"，样本量较小时分数波动更大。
- **语言仅限英文**：题目与上下文均为英文，评测结论不能直接推广到中文或其他语种；对多语言长上下文能力的覆盖有限。
- **长度跨度极大**：上下文从 8,205 词到 1,380,741 词，long 档内部差异悬殊，均值受极值主导。
- **领域异构**：覆盖学术、法律、金融、代码库、对话历史、表格与知识图谱等，不同子任务的 token 密度和推理方式差异明显。

## 8. 结论与后续工作

### 8.1 结论

- gpt-5.6-sol 整体 ACC 60.4%（全量口径 55.3%），覆盖率 91.5%；gpt-6-sol 65.6%（全量口径 59.6%），覆盖率 90.9%。两代均显著高于随机基线 25%。
- **代际对比**：gpt-6-sol 全量口径 Overall +4.3 个百分点；提升集中在易题、Medium 档、长对话历史与长上下文学习；超长上下文（Long 全量 40.7%）、代码库（全量 44.0%）、政务文本三类短板未改善。
- 未评测样本：5.6 为超窗 39、敏感词 3、政策 1，另有 Invalid 3；gpt-6 为超窗 42、敏感词 4、政策 0，另有 Invalid 13。
- 两种口径差距集中在 long 档与 Code 大类；失败主要来自外部限制（窗口、平台审核）与长上下文筛选偏差。
- **对比局限**：两批跑批本地预判阈值不一致，超窗数含本地拦截；Invalid 在 gpt-6 上增多，长对话等子任务样本量较小，结论需在统一口径下复核。

### 8.2 后续工作

1. 统一两模型的本地阈值并补跑临界题，区分"本地预判拦截"与"服务端真实超窗"，在同口径下复核长上下文对比。
2. 针对超窗题：尝试更大窗口模型，或引入分段检索（RAG）、分块摘要后再评测。
3. 针对审核拦截：换渠道定向重试拦截样本，确认是否为网关统一策略；必要时联系平台侧确认。
4. 针对 Invalid：强化 prompt 中"必须从 A/B/C/D 选择"的约束，统计犹豫题型分布。
5. 在 rsi-flow 流程编排框架中验证 Agent 结构，探索长上下文任务的分阶段处理方案。
