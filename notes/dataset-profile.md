# LongBench v2 基线实验与数据集分析报告

## 1. 基本信息

- **数据集**：LongBench v2（THUDM），共 **503** 条英文四选一选择题，用于评测长上下文理解与推理能力。
- **字段**：`_id`、`domain`（大类）、`sub_domain`（子任务）、`difficulty`（easy/hard）、`length`（short/medium/long）、`question`、`choice_A~D`、`answer`、`context`。
- **评测方式**：0-shot，模板要求模型输出 `The correct answer is (X)`；正则抽取 A/B/C/D，与标准答案比对，抽不到记 0。
- **答案分布**：A=96、B=127、C=148、D=132，无明显单一选项偏向，随机蒙题基线为 25%。
- **数据来源**：HuggingFace `THUDM/LongBench-v2`；论文 arXiv:2412.15204。

## 5. 基线实验设置与结果

### 5.1 实验设置

- **模型**：gpt-5.6-sol（经 Thingo OpenAI 兼容网关调用）。
- **参数**：temperature 0.1，0-shot，max_tokens 1024。
- **评测口径**：ACC = 答对条数 / 成功评测条数；失败样本不计入分母。

### 5.2 汇总结果

**概览**

| Model | N | Total | Coverage | Invalid | Fail(窗/敏/政) |
|---|---|---|---|---|---|
| gpt-5.6-sol | 460 | 503 | 91.5% | 3 | 39/3/1 |

**难度与长度（成功口径 / 全量口径，%）**

| Model | Overall | Easy | Hard | Short | Medium | Long |
|---|---|---|---|---|---|---|
| gpt-5.6-sol | 60.4 / 55.3 | 65.7 / 60.9 | 57.1 / 51.8 | 61.7 / 61.7 | 57.1 / 56.3 | 67.6 / 42.6 |

**六大类领域（成功口径 / 全量口径，%）**

| Model | SD-QA | MD-QA | LIL | Dialogue | Code | Structured |
|---|---|---|---|---|---|---|
| gpt-5.6-sol | 57.0 / 56.0 | 60.5 / 57.6 | 62.9 / 54.3 | 51.3 / 51.3 | 71.0 / 44.0 | 75.9 / 66.7 |

> 列名缩写：SD-QA=Single-Document QA，MD-QA=Multi-Document QA，LIL=Long In-context Learning，Dialogue=Long-dialogue History Understanding，Code=Code Repository Understanding，Structured=Long Structured Data Understanding。

### 5.3 口径说明

- 成功 460 条、失败 43 条，覆盖率 91.5%。
- **成功口径**：ACC 分母为 460 条成功样本；**全量口径**：分母为全量 503 条，失败与 Invalid 记 0，正确 278 条，全量 Overall ACC = 55.3%。
- 两种口径差异主要来自超窗样本：Long 档成功口径 67.6%、全量口径 42.6%；Code 大类 71.0% → 44.0%。
- Invalid 3 条为模型未输出选项字母，按官方口径记 0。

## 6. 模型能力分析

> 以下结论基于 460 条成功样本；受超窗幸存者偏差影响，long 档与 Code 档分数需谨慎解读（见问题 5）。

### 6.1 整体水平

- 整体 ACC 60.4%（全量口径 55.3%），高于四选一随机基线 25%，说明模型具备基本的长上下文理解与选择能力；但距官方报告中强模型水平（如 GPT-4o 50.1%、o1-preview 57.7%、人类 53.7%）的对比需在同口径下进行，本结果仅作基线参考。
- 预测分布（A=94、B=122、C=122、D=119）与标准答案分布（A=86、B=116、C=137、D=121）基本吻合，没有明显偏向某一选项，未出现靠固定猜某个字母蒙分的现象。

### 6.2 分能力维度解读

| 能力维度 | 对应任务 | 表现 | 分析 |
|---|---|---|---|
| 结构化数据理解 | Table QA、Knowledge graph reasoning、Structured Data 大类 | Table QA 66.7%、KG reasoning 85.7%、Structured 大类 75.9% | 对表格、知识图谱等结构化信息的抽取与关系推理相对较强 |
| 长上下文学习（In-context Learning） | Many-shot learning、LIL 大类 | Many-shot 71.4%、LIL 大类 62.9% | 能从长上下文里归纳规律并迁移到新样本，少样本学习能力尚可 |
| 代码库理解 | Code repo QA | 成功口径 71.0%（31/50），全量口径 44.0% | 可评测样本上表现尚可，但 19 条超窗未评测；全量口径下明显回落，结论受样本筛选影响 |
| 事件时序推理 | Event ordering | 85.0% | 对长文本中事件先后顺序的梳理能力较强 |
| 单文档/多文档阅读理解 | Academic、Legal、Literary、Financial、Multi-news、Detective 等 | 多在 56%～62% 区间 | 常规长文档问答处于中等水平，跨文档整合未见明显优势 |
| 长对话历史理解 | Dialogue history QA、Agent history QA | Dialogue 42.1%、Agent history 60.0% | 对用户-助手式长对话历史的记忆与回溯较弱；多 Agent 交互历史相对好一些 |
| 政务/政策类文本理解 | Governmental | 37.5%（easy 77.8% / hard 25.8%） | 简单题尚可，难题显著下滑，对需要深度辨析的政策类长文理解薄弱 |

### 6.3 难度与长度上的表现

- **难度**：Easy 65.7% 高于 Hard 57.1%，符合预期；难题上模型更容易被干扰信息带偏。
- **长度（需结合偏差解读）**：成功口径 Short 61.7%、Medium 57.1%、Long 67.6%；换到全量口径为 61.7%、56.3%、42.6%。Long 档在成功口径下偏高，不能说明"越长越强"——long 档 108 条中有 40 条超窗未评测，留存的是相对更易处理的样本；全量口径下 Long 掉到 42.6%，反超长上下文是主要短板。交叉看 easy-long 78.1%、hard-long 58.3%，难度仍是比长度更强的影响因素。
- **难度×长度交叉**：hard-medium 52.8% 为各交叉桶最低，中等长度的难题对模型最不友好；easy-short 62.7%、hard-short 61.2%，短文本上难度差异被压缩。

### 6.4 薄弱环节小结

1. **长对话历史回溯**：Dialogue history QA 42.1% 是所有子任务中最低之一，模型对多轮对话中早期信息的定位与记忆不足。
2. **高难度政策/政务文本**：Governmental 难题仅 25.8%，复杂政策表述下的辨析能力薄弱。
3. **超长上下文承载**：39 条超窗直接无法评测，模型在百万词级场景下受窗口硬限制，不具备直接处理能力。
4. **格式遵循**：3 条输出"none of the above"未按要求给选项字母，指令遵循在不确定时会松动。

## 7. 已发现的问题

### 问题 1：超长上下文超出模型窗口（39 条）

- **现象**：39 条因上下文超过模型上下文窗口未评测，占失败总数的 90.7%；词数范围 17.1 万～138.1 万，绝大多数集中在 long 档。
- **分布**：Code repo QA 19 条、New language translation 9 条，其余散落在 Academic、Table QA、Financial、User guide QA、Legal、Governmental、Knowledge graph reasoning、Literary。
- **成因**：模型单次上下文存在硬上限；代码、数字、专名的 token 密度高于普通英文，同样词数占用更多 token；百万词级题目超出任何单窗口模型的直接处理范围。
- **影响**：long 档、Code 档被超窗筛掉一批最难/最长样本，剩余样本的准确率存在幸存者偏差。
- **后续方向**：更换更大上下文窗口的模型；分段检索（RAG）后再送入模型；分块摘要或递归压缩。

### 问题 2：平台敏感词审核拦截（3 条）

- **现象**：3 条返回 `500 sensitive_words_detected`，全部属于 New language translation；词数 9.6 万～19.4 万。
- **成因**：其中 2 条 context 为政府工作报告壮汉平行语料，中文译文含政务表述，被网关关键词审核命中；审核发生在模型推理之前。
- **性质**：属于外部平台限制，非模型能力问题；本地修改 prompt 措辞无法绕过，同一内容重试仍被拦截，且会产生输入计费。
- **后续方向**：更换审核策略不同的渠道重试；通过检索只送相关片段；联系平台管理员确认是否误判并评估放行。

### 问题 3：内容政策拦截（1 条）

- **现象**：1 条 Financial 题目返回 `400 Request blocked by content policy`，输入 171,530 token；题目涉及加密货币（cryptocurrency）现金流，来源为矿企 SEC 10-K 年报。
- **成因**：话题级内容政策拦截，与上下文长度无关；报错注明 "Normal input charge applied"，被拦仍计输入费用。
- **性质**：平台政策限制，本地无法解除；与敏感词关键词过滤属于不同层级的审核。
- **后续方向**：换渠道重试确认是否复现；如仍被拦，归入政策拦截未评测，不计入准确率。

### 问题 4：模型拒答/未按格式输出（3 条 Invalid）

- **现象**：3 条成功写入结果但抽不到 A/B/C/D，`pred=None`；模型回复为 `none of the above` / `none of the listed choices`。
- **分布**：Many-shot learning 1、User guide QA 1、Governmental 1；标准答案分别为 D、A、C。
- **成因**：LongBench v2 四个选项中仅有一个正确答案，不存在"以上都不是"选项；模型判断四个选项均不匹配，未按要求输出选项字母。
- **口径处理**：按官方规则，抽不到 `The correct answer is (X)` 记 0，计入错误；这 3 条属于格式/解析失效，与明确选错字母的样本应区分记录，但不人为猜测其意图选项。

### 问题 5：幸存者偏差导致分桶结果不可直接横向比较

- **现象**：失败样本高度集中于 long 档（40/43）和少数 medium；Code Repository Understanding 原始 50 条仅成功 31 条（19 条超窗），Long 档原始 108 条仅成功 68 条。
- **成因**：超窗淘汰的是最长、最难的一批样本，留存样本被筛选过一轮；各分桶的样本基数和难度结构不一致。
- **影响**：表中 Long 档 67.6% 高于 Short 61.7%、Code 档 71.0% 偏高，不能直接解读为"模型越长文/代码越强"；小样本分桶（Code 31 条、Structured 29 条）方差更大。
- **处理建议**：报告分桶准确率时同时标注各桶成功样本数；跨桶比较需结合覆盖率与样本构成谨慎解读。

### 问题 6：数据集本身的结构特点

- **任务类型**：全部为四选一选择题，评分可靠（ACC），避免了生成式任务的主观评分；但也限制了对自由生成能力的评测。
- **选择题存在随机蒙对空间**：四选一随机基线为 25%，模型在不确定时仍有 1/4 概率蒙对；单题准确率无法区分"真正理解"与"侥幸猜中"，样本量较小时分数波动更大。
- **语言仅限英文**：题目与上下文均为英文，评测结论不能直接推广到中文或其他语种；对多语言长上下文能力的覆盖有限。
- **长度跨度极大**：上下文从 8,205 词到 1,380,741 词，long 档内部差异悬殊，均值受极值主导。
- **领域异构**：覆盖学术、法律、金融、代码库、对话历史、表格与知识图谱等，不同子任务的 token 密度和推理方式差异明显。

## 8. 结论与后续工作

### 8.1 结论

- 在可评测的 460 条样本上，gpt-5.6-sol 整体 ACC 为 60.4%（全量口径 55.3%），覆盖率 91.5%。
- 未评测的 43 条可分为三类：超窗 39、敏感词拦截 3、政策拦截 1；另有 3 条格式失效。
- 两种口径差距集中在 long 档与 Code 大类（全量口径分别降至 42.6%、44.0%），超长上下文承载是主要短板；短/中长文本表现相对稳定。
- 失败主要来自外部限制（窗口、平台审核）与长上下文筛选偏差。

### 8.2 后续工作

1. 针对超窗题：尝试更大窗口模型，或引入分段检索（RAG）、分块摘要后再评测。
2. 针对审核拦截：换渠道定向重试 4 条拦截样本，确认是否为网关统一策略；必要时联系平台侧确认。
3. 补充多模型对比，统一在相同覆盖率口径下比较各模型表现。
4. 在 rsi-flow 流程编排框架中验证 Agent 结构，探索长上下文任务的分阶段处理方案。
